# Independent Image Studio

Image Studio lives at `/app/images` and saves standalone images to the private media library. It reuses the configured OpenAI image model, versioned standalone prompt, quality/size pricing and reference validation used by MCP. A project or AI-client connection is unnecessary. Existing MCP generation permissions and advisory budgets continue to use their own path.

Owners and editors can enter a prompt, choose square/landscape/portrait and low/medium/high quality, select ready PNG/JPEG/WebP references, review a signed ten-minute estimate and explicitly generate one image. Results can be downloaded, attached to Social drafts or reused in a project scene through the existing library flow. Project scene review still applies when an image is assigned.

The browser flow checks current identity, workspace membership and generation permission, enforces existing workspace daily/monthly budgets, reserves estimated usage atomically and records actual usage. Quote signatures bind the user, workspace, exact request, model, references and pricing. A saved idempotency key returns the existing job; a changed request conflicts. Queue handoff retries target the existing job and never automatically repeat provider work. Each job has one provider attempt. Uncertain submission costs retain the recorded or conservative estimate.

`library_image_jobs` holds requests, frozen plans/prompts, provider request IDs, status and cost. `usage_reservations.library_image_job_id` is a tenant-constrained optional link. The existing operation invariant still requires exactly one operation identity. Marketing data is not used. The existing 30-minute recovery pass settles expired browser-image reservations. No recurring schedule is added or made more frequent.

Deploy the matching `library-image-generation` worker and web app after the migration. Existing scene-image flags, provider keys, model and pricing settings are reused. No environment variable or dependency is added. Google video and ElevenLabs visual access holds apply independently.

Initial Image Studio supports the configured OpenAI image model and one output per request. ElevenLabs visual API access remains subject to the existing subscription/licensing controls. History is workspace scoped, paginated and polls only while this page shows unfinished jobs. Provider and worker verification uses mocks without paid generation.

## Viewing and editing results (2026-11-23)

Click a completed image to open a viewport-bounded shadcn Dialog with a large contain-fit preview, download and Edit image controls. Only an open viewer mounts the larger preview. Escape/Close restores focus to the thumbnail. Failed or expired previews offer an authenticated, workspace-scoped refresh of the private URL. Viewers retain viewing access; generation permission and the image-generation feature flag are required to edit.

Edit image loads the saved, ready source original and its canvas/quality. The user describes specific changes and reviews a signed ten-minute estimate before creating an edited version. The web service constructs versioned preservation instructions in the prompts package and sends the source image as the sole reference through the existing frozen-plan, idempotent image workflow. The existing provider already selects OpenAI `images.edit` when references are present, including its existing high-fidelity behavior. See [OpenAI image-edit documentation](https://developers.openai.com/api/reference/resources/images/methods/edit). Each edit is a billable new output; no guarantee of unchanged pixels outside the requested changes is made. Mask painting and pixel-region replacement are not included.

The original job/file, scene assignments and Social attachments are not overwritten. The new job's saved request and frozen reference/ETag record identify its source. Its history card shows the requested changes, while the complete rendered edit prompt stays saved for reproducibility. Canvas dimensions are inherited from the source; quality remains selectable. Stale cost quotes, deleted/unready/cross-workspace sources and missing permissions are rejected before provider submission by shared services. Retrying the same saved request reuses its idempotency key and does not duplicate paid work. Existing MCP generation/autonomy is unchanged. No schema, environment, dependency, provider or worker-deployment change is needed because the current worker accepts the fully rendered prompt and reference snapshot.
